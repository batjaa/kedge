6. Rendering pipeline

Imported documents are untrusted input. The pipeline normalizes Markdown, MDX, and HTML into one projection, and every stage fails soft: unknown fence languages fall through to plain-text highlighting, and an MDX compile failure renders the plain-markdown fallback with a banner rather than a broken page.

MDX is code, so imports and exports are rejected outright and only the component allowlist may render. The fallback path must be byte-identical to the plain-markdown renderer so a hostile document cannot probe for differences.

6.2 Diagrams

Kroki is the sole diagram engine, self-hosted in both editions. Fenced blocks on the engine allowlist render server-side and cache by content hash:

render-pipeline · mermaid Kroki

Only the explicit allowlist is ever forwarded to the Kroki container:

config example fence
yaml lib/remark-diagrams.ts → engine allowlist 
engines:
  - plantuml
  - mermaid
  - d2
  - graphviz
  - excalidraw
cache: content-hash   # survives re-sync
timeout_ms: 4000       # then show-source error panel

A render failure never blanks the section — the fence collapses into a show-source error panel with the engine's stderr, and the rest of the page renders normally.
