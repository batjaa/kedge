Comment Re-anchoring Across Document Versions

A review comment is only useful if it survives the document it reviews. This RFC defines how Margin keeps threads attached — or honestly orphaned — as specs evolve underneath them.

Motivation

Authors revise specs continuously while review is underway; a comment pinned to character offsets alone is destroyed by the first edit. We bind anchors to the rendered plain-text projection rather than the markdown source, so cosmetic markup changes never move a highlight.

Anchor model

Each anchor follows the W3C Web Annotation selector shape. Its properties:

Properties

  • exact string

    The selected text, verbatim, from the plain-text projection.

  • prefixstring

    Up to 64 characters of context before the selection; used for disambiguation.

  • startinteger

    Character offset into the projection — a hint, never trusted on its own.

  • projection_versioninteger

    Version of the extraction algorithm this anchor was created against.

Anchor
obj threads/512/anchors/v4 
{
  "exact":  "similarity threshold of 0.75",
  "prefix": "fall back to fuzzy matching with a ",
  "start":  10412, "end": 10441,
  "projection_version": 1
}

Re-anchoring algorithm

job ReanchorThreadsJob · per thread, on every sync

Three attempts, in order: an exact context match; then a fuzzy match with a similarity threshold of 0.75; and finally the thread is set aside as orphaned rather than guessed.

Orphaned threads

An orphaned thread is never discarded. It keeps its original quotation and waits in a tray at the foot of the margin, where the author can re-attach it to new text with a single selection.
