# Spec: M3.9 — Web-UI internationalization

> Third module of the 2026-07-23 design-lock split ([M3.7](m3.7-design-refresh.md) → [M3.8](m3.8-activity-landing.md)
> → **this**). Runs last deliberately: the catalog sweep touches every string the earlier modules produce.
> Locales: **en-US (source) · es-US · mn-MN · de-DE** (user-directed at speccing). Eng-review decisions
> (2026-07-23) inlined by issue number.

## Problem Statement

The UI speaks only English, which walls off reviewers who would happily comment in their own language — including the founder's (Mongolian). Documents are the users' content in whatever language they wrote; the chrome around them shouldn't force English on the review conversation.

## Solution

Internationalize the web UI chrome with next-intl: en-US as the authored source, es-US, mn-MN, and de-DE catalogs, browser-language negotiation with a persisted manual switcher. Document content is never translated.

## User Stories

1. As a reviewer whose browser is set to Spanish, German, or Mongolian, I want the UI chrome in my language automatically, so that commenting doesn't require English.
2. As a user, I want a language switcher to override the detected locale, persisted across visits, so that negotiation never traps me in the wrong language.
3. As a guest on the shared-doc surface, I want the switcher available there too, so that invited reviewers aren't stuck with the doc owner's language.
4. As a Mongolian user, I want dates, numbers, and plurals formatted correctly for mn-MN (and likewise es-US/de-DE), so that translations feel native, not templated.
5. As any user, I want a missing translation to render English, never a raw message key, so that catalog gaps degrade invisibly.
6. As an anonymous visitor, I want the landing localized, so that the first impression works in my language.

## Implementation Decisions

- **Library: next-intl in its documented "without i18n routing" mode** — cookie-based locale, no URL prefixes this pass; hreflang/SEO alternates for the landing are Launch-tail work. ICU MessageFormat throughout (CLDR plural rules cover Mongolian).
- **Locale resolution** (4A): the cookie value is validated against a **strict allowlist** of the four supported locales; anything else falls through to Accept-Language negotiation, then en-US. The switcher (header/settings + landing footer + shared-doc surface) sets the cookie via a server action and refreshes.
- **Fallback** (B1): en-US messages are **deep-merged under every locale** so a missing key renders English; dev-time missing-key logging; a CI **key-parity test** asserts every key exists in all four catalogs (rot guard).
- **Display font per locale** (12A): Space Grotesk has no Cyrillic — for mn-MN the display token resolves to the **system stack wholesale** (M3.7 built the token locale-conditional), so Mongolian headings are consistent, never per-glyph ransom-note fallback. Watch upstream (Cyrillic PR) and revisit when it ships.
- **Chip strings are a constrained glossary** (13A): status/chip messages carry translator-facing max-length notes in the catalog; German equivalents chosen deliberately short ("OFFEN", "PRÜFUNG"); a truncation safety class on chips as belt-and-braces. Chips are labels, not prose.
- **Scope: web-owned strings only** — app/auth/shared/demo/landing chrome, activity sentences, empty/error states. Document content never translated. API prose passes through as-is; where the `sync_error_code` debt item lands machine-readable codes, the web maps code → localized string with prose fallback. The `/docs` dogfood shell stays English.
- Dates/numbers via `Intl` on the active locale (relative times included).
- Catalog provenance: en-US authored; mn-MN founder-reviewed; es-US/de-DE machine-seeded and **gated on native review before Launch** (TODOS user action).

## Testing Decisions

Existing three seams.

- **Journeys**: *i18n* (Accept-Language es-US renders translated chrome; switcher to mn-MN persists across reload; **guest switcher works on the shared-doc surface**).
- **Web vitest**: locale negotiation unit (allowlist, garbage cookie → negotiation → en-US, 4A); **missing key renders the en-US string, not the key path** (B1); catalog key-parity across all four; chip-glossary length lint (longest de chip string fits the truncation budget); mn display-token resolution (12A).
- **API PHPUnit**: none — this module doesn't touch the API.

## Out of Scope

- URL-prefixed locales, hreflang, localized OG/meta for SEO (Launch tail).
- Wholesale API error-prose translation (code-mapping path only).
- Translating document content, comments, or any user-authored text — ever.
- `/docs` dogfood shell i18n.
- Additional locales beyond the four (adding one = catalog + allowlist entry; deliberately cheap later).

## Further Notes

- Standing cost, eyes open: every future user-facing string is a four-catalog obligation; the parity test makes the cost visible at CI time instead of at runtime.
- Reversibility is the lowest of the three modules (~2/5) — extraction doesn't un-thread. That's why it runs last, against stable strings.
