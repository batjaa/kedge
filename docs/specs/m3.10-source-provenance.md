# Spec: Source provenance

> Module M3.10 on `docs/ROADMAP.md` (wedge, decided 2026-07-24). Scope source: SPEC §11 (provenance-display amendment 2026-07-24), §21 M3.10; language: CONTEXT.md (Project = container, Source = origin). Decision context: TODOS.md decision log 2026-07-24. Specced 2026-07-24; not yet eng-reviewed.

## Problem Statement

Every document row looks the same. A doc imported from `docs/rfcs/017-anchoring.md` in a tracked repo is indistinguishable from a pasted scratch note: the list shows title, lifecycle, threads, and sync state — nothing about where the document came from. The hierarchy a repo already gave us is erased at the door, so a project holding a repo-full of docs reads as an unordered pile, and finding "the RFCs under `docs/rfcs/`" means recognizing titles. The data is all there and displayed nowhere: `documents.tracked_path` (the scan diff key), `source_type`, `source_url`.

The fix is deliberately **not** folders. CONTEXT.md pinned the organization language — a Project is the container, a repo is a Source, never the container — and SPEC §2 keeps wikis/folders a non-goal. Projects stay the only user-managed hierarchy; repo structure becomes **visible, read-only, derived metadata** inside it.

## Solution

Three thin layers over data we already store:

1. **Provenance chip on every row.** Repo-sourced docs show their repo-relative path (`docs/rfcs/017-anchoring.md`); standalone GitHub imports show `owner/repo` + path; raw-URL imports show the source host; uploads/pastes show a pasted-content label. Mono chip idiom, left-truncated to keep the filename visible, full value on hover.
2. **Project pages group repo docs under their Source.** Each attached tracked repo becomes a section: its docs ordered by path (server-side, paginated), with subtle divider rows when the directory changes — a flattened tree, not a folder UI. Docs not from an attached repo sit in an "Other documents" section, newest-first as today.
3. **Derivation lives server-side, in one place.** The list resource ships a small display-ready `source` descriptor; the web renders, never parses. Same rationale as projection ownership (SPEC §5.4): two parsers drift.

A "group by: project / source" toggle on the home list is **deferred** until the chips have been lived with (decision log 2026-07-24).

## User Stories

1. As an author, I want every document row to show where the doc came from — repo path, repo + path, source host, or "pasted" — so that provenance is legible at a glance without opening the doc.
2. As an author, I want a project page to group its repo-sourced docs under their tracked repo, ordered by repo path, so that the repository's own structure is how I scan a repo-full of imports.
3. As an author, I want directory changes within a repo section marked by a divider, so that `docs/adr/` and `docs/specs/` read as clusters without becoming navigable folders.
4. As an author, I want docs that aren't from an attached repo in a clearly labeled "Other documents" section (newest-first, as today), so that grouping never hides anything.
5. As an author whose tracked repo was deleted, I want its docs to keep showing their repo path chip, so that un-tracking (which keeps documents) never erases provenance.
6. As a maintainer, I want provenance derived server-side in one tested place and shipped as strings, so that the web never re-implements blob-URL parsing and the row payload stays lean.
7. As a maintainer, I want path ordering and the tracked-repo filter applied at the database inside the same workspace-scoped query definition, so that grouping costs no extra queries and discloses nothing the flat list wouldn't.
8. As a screen-reader user, I want the provenance chip and section headers announced as text (not sight-only layout), so that grouping is perceivable without vision.

## Implementation Decisions

**Provenance descriptor (api).** A small value object / resource method — one derivation site, unit-tested — added to `DocumentListResource` (and mirrored in `web/lib/document-types.ts` under the accepted hand-sync debt):

```
source: {
  kind: 'repo' | 'github' | 'url' | 'upload',
  path?: string,     // repo: tracked_path · github: blob path
  repo?: string,     // github: "owner/repo"
  host?: string,     // url: source hostname
}
```

- `kind: 'repo'` when `tracked_path` is set — **including when `tracked_repo_id` was nulled by un-track/delete** (story 5): the path column survives and still names the doc's origin.
- `kind: 'github'` for `github_public`/`github_pat` docs without a `tracked_path`: parse `source_url` with the same segment logic as `AbstractGithubBlobConnector::parse` — **extract that parser to a shared support class** (`GithubBlobUrl`) consumed by both; do not duplicate it. Unparseable URL → fall through to `kind: 'url'` (never null, never a 500 — untrusted input rule).
- `kind: 'url'` for `raw_url`: `host` = hostname of `source_url` (no path — raw URLs are long and low-signal).
- `kind: 'upload'` for `upload` (paste and file upload share the connector; the web labels it "pasted").
- `tracked_repo_id` is also added to the row payload — the project page's bucketing key against its attached-repos list. Nothing else grows; no content, no `source_meta` passthrough.

**List endpoint (api).** `GET /api/v1/documents` (the one shared query definition, M3.7 7A) gains:
- `?tracked_repo=` filter (numeric id, workspace-scoped exactly like `?project=` — a foreign repo id yields an empty page, never a 403 oracle).
- `?order=path` — `orderBy('tracked_path')->orderByDesc('id')` tiebreak; validated to require the `tracked_repo` filter (path order is meaningless across sources). Default order unchanged.
- The existing standalone `tracked_path` index covers the sort; no migration in this module.

**Web.**
- **Chip**: one new `SourceChip` beside the project chip in the row anatomy, rendering the descriptor per kind: `path` · `repo · path` · `host` · "pasted". CSS left-truncation (`direction: rtl` trick or `text-overflow` on a reversed flex) keeping the basename visible; `title` attr carries the full value. Home list and project page share the row component, so the chip appears everywhere at once.
- **Project page sections**: the page already loads its attached tracked repos; for each, fetch `?project=&tracked_repo=&order=path` and render a section headed by the repo's short name (`owner/repo`), each with its own "Load more". Remaining docs (`?project=` minus attached-repo docs — implemented as the existing project query excluding rows whose `tracked_repo_id` is in the attached set, via a `?tracked_repo=none`-style exclusion param if a second query is needed; decide at implementation, but it must stay one DB-paginated query per section) render under "Other documents", newest-first, same as today. A repo section with zero docs collapses to the header + "no documents yet from this source".
- **Directory dividers**: derived client-side from the loaded rows — a non-interactive divider row whenever `dirname(path)` differs from the previous row. Within-page only by construction (rows arrive path-ordered, so a page boundary can at worst repeat a dirname header, never interleave). Not links, not folders.
- **Home list unchanged structurally**: project grouping stays primary; the chip is the only addition (the group-by-source toggle is the deferred follow-up).
- **i18n note**: this module adds chip/section strings ("pasted", "Other documents", divider labels). It lands **before M3.9 i18n** so the i18n glossary snapshots stable strings — recorded as an M3.9 dependency on ROADMAP.

**Design.** DESIGN.md chip idiom: mono, neutral hue (provenance is metadata, not status — no status colors). Section headers reuse the project-page's existing header scale; divider rows are hairline + dirname in the muted mono style. No new tokens, no webfonts.

**Testing.**
- *PHPUnit:* derivation matrix — tracked doc → `repo`+path; un-tracked survivor (null `tracked_repo_id`, path set) → `repo`; standalone blob URL → `github` owner/repo+path; unparseable github URL → `url` fallback; `raw_url` → host; `upload` → upload. Endpoint: `tracked_repo` filter workspace-scoped (IDOR matrix extension — foreign repo id → empty, not error); `order=path` ordering + tiebreak; `order=path` without `tracked_repo` → 422; payload adds only `source` + `tracked_repo_id`.
- *Vitest:* chip render per kind incl. truncation `title`; divider derivation (dirname change, page-boundary repeat tolerated); project-page bucketing (attached repo → section, un-attached/other → "Other documents", empty section state).
- *E2E (dogfood):* extend the M3.6 tracked-repo journey — track a repo, open the project page: repo section lists docs in path order with a directory divider, rows carry path chips; a pasted doc shows the "pasted" chip in "Other documents". Home rows show the same chips.
