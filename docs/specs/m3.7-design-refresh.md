# Spec: M3.7 — Design refresh (Open Harbor), dashboard, activity, landing & i18n

> Wedge module, added 2026-07-23 from the design lock (DESIGN.md amendment + `docs/designs/app-*.html`).
> Scope set by user decision at speccing: full option set — restyle + dashboard upgrade + workspace General
> + activity feed + marketing landing + web-UI i18n (en-US · es-US · mn-MN · de-DE).

## Problem Statement

The product works but no longer matches its own approved design. The locked Open Harbor baseline is light-first with a display font; the app still defaults to dark with system-only type. The authenticated home is a bare import box over a list — no at-a-glance workspace state (counts, orphans, stale approvals), no filtering, no visibility into what happened while you were away. The anonymous SaaS home is a paste box that renders docs but sells nothing — a stranger has no idea what Kedge is before pasting. And the UI speaks only English, which walls off reviewers who would happily comment in their own language.

## Solution

Apply the locked baseline across every surface (light default, warm register, Space Grotesk display headings, amended chip/button recipes). Grow the authenticated home into the mocked dashboard: projects rail, stats strip, lifecycle filters, and an activity feed read from the audit log. Give workspace settings its General card (rename). Replace the anonymous SaaS home with the Open Harbor marketing landing whose hero *is* the existing demo import. Internationalize the web UI in four locales with browser-language negotiation and a manual switcher.

## User Stories

1. As a signed-in user, I want the app to open in the warm light theme by default, so that it matches the approved design — and my explicit theme choice (dark) still persists per device.
2. As a reader, I want headings and titles in the display face (Space Grotesk) with body text on system fonts, so that pages have the locked visual identity without webfont cost on prose.
3. As a user, I want every chip, panel, and button to follow the amended DESIGN.md recipes in both themes, so that no surface looks like the old register.
4. As an author, I want a stats strip on my dashboard (documents, open threads, orphans, stale approvals, imports in flight), so that I see workspace health without opening anything.
5. As an author, I want a projects rail on the dashboard (project cards with doc/thread/orphan counts, Unfiled bucket), so that I can jump into a project in one click.
6. As an author, I want to filter the documents table by lifecycle (all / in review / approved / draft / needs attention), so that a long list stays navigable — and the filter must be correct across pagination, not just the loaded page.
7. As an author, I want a "Recent activity" feed (replies, accepted suggestions, re-scans, orphaned threads, imports settling), so that I can catch up after time away.
8. As an author, I want each activity row to link to its target (document section, project), so that catching up is one click, not a search.
9. As a workspace owner, I want to rename my workspace and edit its slug in Settings → General, so that the name shown across the app is mine, not a default.
10. As an anonymous SaaS visitor, I want a real landing page — what Kedge is, what's shipped, what's coming, self-host story — with the paste-a-URL demo in the hero, so that I understand the product before I try it.
11. As an anonymous visitor on a self-hosted instance, I want the sign-in branch unchanged (no marketing page), so that a private instance stays private-feeling.
12. As a reviewer whose browser is set to Spanish, German, or Mongolian, I want the UI chrome in my language automatically, so that commenting doesn't require English.
13. As a user, I want a language switcher to override the detected locale, persisted across visits, so that negotiation never traps me in the wrong language.
14. As a Mongolian user, I want dates, numbers, and plurals formatted correctly for mn-MN (and likewise es-US/de-DE), so that translations feel native, not templated.
15. As a reviewer on the shared-doc surface, I want the restyle and my locale applied there too, so that the guest experience matches the product.
16. As a user on the M5-less present, I want the Queue nav item visibly ghosted ("M5"), so that the roadmap is honest in-product rather than a dead link.

## Implementation Decisions

**Restyle (applies product-wide: app shell, auth, shared/guest, demo, error surfaces).**
- Default theme flips to light; the theme provider keeps per-device persistence and the existing toggle. The standalone error surface (currently hard-coded dark) follows light-first.
- Light register per amended DESIGN.md: page `stone-50`, white cards, `-700` chip hues; dark unchanged (original zinc register). The Fumadocs token overrides (`--color-fd-*`) re-map accordingly; tokens stay expressed as theme variables.
- **Space Grotesk self-hosted** (OFL — license file committed with the woff2s; no runtime Google Fonts fetch), exposed as a display font token so headings/wordmark/page+panel titles opt in via one utility. Body/UI/prose stay on system stacks.
- Header per the locked mockup minus search: brand, nav (Documents; ghosted Queue chip "M5"), theme toggle, Import action, avatar. **No ⌘K/search pill** — cross-document search is a v1 non-goal (SPEC §Out of scope). **No Projects nav item** — the dashboard rail is the projects navigation; a `/projects` index page is not built.
- Solid-emerald CTA variant (light) reserved for hero/approve actions per DESIGN.md.

**Dashboard (authenticated home).**
- At desktop widths the home becomes rail + table per the mockup: left rail of project cards (existing projects data + per-project counts), Unfiled bucket, and the ghosted M5 queue card; right, the existing live documents table (retaining settle-in-place polling, inline retry, project re-filing). Narrow viewports keep the current single-column grouped list.
- **New aggregate endpoint: workspace summary counts** — documents total, per-lifecycle counts, open threads, orphaned threads, stale approvals, imports in flight. One Policy-guarded, workspace-scoped read powering both the stats strip and the filter-chip counts. Counts come from queries, not row scans of the paginated list.
- **Lifecycle filter becomes a server-side list parameter** (correctness across pagination). This amends SPEC §16's "no `?status=` filter is scheduled" note — SPEC updated when this ships. "Needs attention" is a defined composite (failed imports + orphans + stale approvals), computed server-side so chip count and list agree.

**Activity feed.**
- Read model is `audit_logs` (in the schema since day one; `AuditLogger` already writes import/share/project/tracked-repo/re-sync events). New Policy-guarded, workspace-scoped, paginated activity read with a **type allowlist** — only events with a user-facing sentence are exposed.
- **Instrument the review-side gaps**: thread/comment created, suggestion accepted/declined, approval granted/gone-stale, re-anchor outcomes (relocated/orphaned) emitted by the re-anchor job. These writes also serve M5's inbox — the feed is deliberately a subset of what M5 will consume.
- Rendering: actor avatar + localized sentence + target link + relative time. Loaded on page load; **no polling/realtime** (M5 owns liveness). Comment persistence must never depend on audit writes succeeding (hard rule 6 analogue: audit failure is logged, never thrown into the domain action).

**Workspace settings — General.**
- Workspace update endpoint (name, slug): owner-only Policy, slug validated/unique, personal-workspace scoped exactly like the integrations surface. General card sits above Integrations on the existing settings page. No danger zone (workspace deletion is account-deletion territory, out of scope).

**Marketing landing (SaaS only).**
- The anonymous SaaS branch of the root route renders the Open Harbor landing (`variant-3-open-harbor.html` is the mockup of record): hero with the working demo paste box (the existing demo-import flow and its rate limits, unchanged), capability tour, workspace console shot, roadmap cards, self-host CTA, footer.
- Content is **statically authored marketing copy** — curated by hand, not generated from ROADMAP.md (no rot coupling; updating it is an editorial act). Localized like the rest of the UI.
- Self-hosted edition: existing sign-in branch untouched (edition read from the config endpoint, failing closed to self-hosted, as today).

**i18n (web UI chrome).**
- Library: **next-intl** (App Router standard). Message catalogs: **en-US is the authored source**; es-US, mn-MN, de-DE seeded as reviewed translations. ICU MessageFormat throughout (CLDR plural rules cover Mongolian).
- **Locale negotiation, not locale URLs**: Accept-Language → default; manual switcher (header/settings + landing footer) persists an override cookie. No URL-prefixed routes in this pass — hreflang/SEO alternates for the landing are Launch-tail work.
- Scope is **web-owned strings only**: app/auth/shared/demo/landing chrome, activity sentences, empty/error states. Document content is never translated. API prose (e.g. `sync_error`) passes through as-is; where the existing `sync_error_code` debt item lands machine-readable codes, the web maps code → localized string with prose fallback — this module accelerates that debt item for the strings it surfaces, and does not attempt wholesale API-message translation.
- Dates/numbers via `Intl` on the active locale. The `/docs` dogfood shell stays English (dev surface, not product).

**Sequencing inside the module** (guidance for `/to-tickets`): restyle first (every later screenshot/journey lands in the final register) → dashboard + summary endpoint → activity (API writes, then feed) → settings General → landing → **i18n as the final sweep** (catalog extraction touches every string the earlier steps produce; doing it last avoids double-churn).

## Testing Decisions

Existing three seams only (agreed 2026-07-23); no visual-regression baseline seam.

- **Playwright journey pack** (highest seam, primary): new journeys — *dashboard* (seeded workspace: stats strip counts match seeded fixtures; lifecycle filter narrows the list server-side; rail card navigates to the project page; activity feed shows a seeded event linking to its target), *settings-rename* (rename → header/copy reflects it; slug collision rejected inline), *landing* (SaaS env: anonymous visit renders the landing, hero paste runs the existing demo journey's flow; self-hosted env: sign-in branch — edition-gating prior art from the demo-mode journeys), *i18n* (Accept-Language es-US renders translated chrome; switcher to mn-MN persists across reload; light theme is the default `html` state and a toggled choice persists — folded assertions, not a separate theme journey). Existing journeys updated where anatomy changed; behavior assertions stay, selectors churn.
- **Web vitest**: filter/composite ("needs attention") derivation, summary formatting, locale negotiation and catalog completeness (every key present in all four catalogs — a cheap rot guard), activity sentence rendering per type. Prior art: the document-groups and scan-report projection tests.
- **API PHPUnit feature tests**: summary endpoint (fixture matrix across lifecycles/threads/approvals/imports; Policy + workspace scoping), activity endpoint (scoping, type allowlist, pagination, and the new `AuditLogger` write sites firing from their domain actions), workspace update (validation, owner-only, slug uniqueness), lifecycle filter parameter (counts agree with summary). Prior art: the M3.5 documents-list and M3.6 tracked-repo suites.

Good tests here assert external behavior (counts, visible sentences, filtered rows, language of rendered chrome) — never token classnames beyond the light-default `html` assertion, and never catalog internals beyond key-parity.

## Out of Scope

- Cross-document search / ⌘K palette (v1 non-goal; the mockup's pill is aspirational).
- Keep/Archive action on re-scan-flagged deletions (flagging shipped in M3.6; archive semantics undefined — existing debt note stands).
- Visual-regression screenshot seam (declined at seam review).
- URL-localized routes, hreflang/SEO alternates for the landing (Launch tail).
- Wholesale API error-prose translation (code-mapping path only, via the `sync_error_code` debt item).
- Realtime/polled activity, inbox, mentions, digests (M5 owns them; this feed is read-on-load).
- Teams/members surfaces (`app-teams.html` is a post-v1 preview; SPEC §10.1 note governs).
- `/docs` dogfood shell restyle-beyond-tokens and i18n.
