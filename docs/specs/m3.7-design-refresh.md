## Problem Statement

The product no longer matches its own approved design: the locked Open Harbor baseline is light-first with a display font, while the app defaults to dark with system-only type. The authenticated home is a bare import box over a list — no at-a-glance workspace state (counts, orphans, stale approvals), no filtering, and no way to see projects without scrolling grouped headers. Workspace settings can't even rename the workspace.

## Solution

Apply the locked baseline across every surface (light default, warm register, self-hosted Space Grotesk display headings, amended chip/button recipes). Grow the authenticated home into the mocked dashboard: projects rail, stats strip, server-side lifecycle filters. Add the General card (rename/slug) to workspace settings.

## User Stories

1. As a signed-in user, I want the app to open in the warm light theme by default, so that it matches the approved design — and my explicit theme choice (dark) still persists per device.
2. As a reader, I want headings and titles in the display face (Space Grotesk) with body text on system fonts, so that pages have the locked visual identity without webfont cost on prose.
3. As a user, I want every chip, panel, and button to follow the amended DESIGN.md recipes in both themes, so that no surface looks like the old register.
4. As an author, I want a stats strip on my dashboard (documents, open threads, orphans, stale approvals, imports in flight), so that I see workspace health without opening anything.
5. As an author, I want a projects rail on the dashboard (project cards with doc/thread/orphan counts, Unfiled bucket), so that I can jump into a project in one click.
6. As an author, I want to filter the documents table by lifecycle (all / in review / approved / draft / needs attention) with counts on the chips, so that a long list stays navigable — correct across pagination, not just the loaded page.
7. As an author watching an import, I want live rows to stay visible and the counts to stay true while things settle, so that filtering never hides work in flight.
8. As a workspace owner, I want to rename my workspace and edit its slug in Settings → General, so that the name shown across the app is mine.
9. As a user, I want the Queue nav item visibly ghosted ("M5"), so that the roadmap is honest in-product rather than a dead link.
10. As a reviewer on the shared-doc surface (and auth/demo/error surfaces), I want the restyle applied there too, so that guests see the same product.

## Implementation Decisions

**Restyle (product-wide: app shell, auth, shared/guest, demo, error surfaces).**
- Default theme flips to light; per-device persistence and the existing toggle unchanged. The standalone error surface (currently hard-coded dark) follows light-first.
- Light register per amended DESIGN.md: page `stone-50`, white cards, `-700` chip hues; dark maps to the original zinc register. `--color-fd-*` overrides re-map; tokens stay theme variables.
- **Space Grotesk self-hosted** (OFL; license committed with the woff2s; no runtime font fetch), exposed as a display-font token so headings/wordmark/page+panel titles opt in via one utility. Body/UI/prose stay on system stacks. The display token is **locale-conditional by design** (eng review 12A): when M3.9 introduces mn-MN (Cyrillic — Space Grotesk has none), the token resolves to the system stack wholesale for that locale; build the token so that override is one variable, not a sweep.
- Header per the locked mockup minus search: brand, nav (Documents; ghosted Queue chip "M5"), theme toggle, Import action, avatar. No ⌘K/search pill (cross-document search is a v1 non-goal). No Projects nav item — the rail is the projects navigation; no `/projects` index page.
- Solid-emerald CTA variant (light) reserved for hero/approve actions per DESIGN.md.

**Dashboard (authenticated home).**
- Desktop: rail + table per the mockup — project cards (existing projects data + per-project counts), Unfiled bucket, ghosted M5 queue card; the existing live documents table keeps settle-in-place polling, inline retry, project re-filing. Narrow viewports keep the current single-column grouped list.
- **Workspace summary endpoint**: documents total, per-lifecycle counts, open threads, orphaned threads, stale approvals, imports in flight. Policy-guarded, workspace-scoped; powers the stats strip and filter-chip counts. Single-pass conditional aggregates where trivial.
- **Lifecycle filter is a server-side list parameter** (correct across pagination; amends SPEC §16's old "no ?status=" note). "Needs attention" = failed imports + orphans + stale approvals, defined server-side.
- **One query definition** (eng review 7A): lifecycle and needs-attention predicates live once as shared model scopes / one query service consumed by both the summary endpoint and the list filter; a test asserts chip count == filtered total per state. (The tracked-repo triple-encoding debt is the cautionary precedent.)
- **Live rows under a filter** (5A): settled rows keep their place — with their new chip — until the next filter change/refetch; submitting an import flips the active chip to All so the new row is always watchable.
- **Count freshness** (6A): the summary re-fetches whenever a row settles/retries/refiles, piggybacking the existing poller callbacks. No new poll loop.
- **Poller debt bundled** (8A): the open `usePollUntilSettled` caller-owned-deps debt item (TODOS, M3.6) is fixed as the first dashboard ticket — internalize deps via refs-for-callbacks + a `key` param — before the summary refresh becomes its fifth consumer.
- **Degradation** (A1): summary failure → the strip renders nothing and chips lose counts but still filter; the documents list is never blocked. One existing-style degraded banner; matches the project-page outage precedent.

**Workspace settings — General.**
- Workspace update endpoint (name, slug): owner-only Policy, slug validated/unique, personal-workspace scoped like the integrations surface. General card above Integrations. **The rename writes an audit event** (11A) with old→new in meta — M3.8's feed allowlists it. No danger zone (workspace deletion is account-deletion territory).

## Testing Decisions

Existing three seams only (agreed 2026-07-23): Playwright journey pack, web vitest, API PHPUnit.

- **Journeys**: *dashboard* (seeded workspace: stats match seeds; lifecycle filter narrows server-side; chip counts agree with rows; rail card navigates to the project page); *settings-rename* (rename reflects in chrome; slug collision rejected inline); light-default assertion + toggle persistence folded into an existing journey. Existing journeys updated where anatomy changed — behavior assertions must survive untouched (selector churn only, no regressions).
- **Web vitest**: needs-attention composite derivation; settled-row-retained-until-refetch + import-flips-filter-to-All (5A); settle event triggers summary re-fetch (6A); degraded render without strip/counts (A1); `usePollUntilSettled` internalized deps + key (8A). Prior art: workspace-home and use-poll-until-settled suites.
- **API PHPUnit**: summary endpoint fixture matrix (lifecycles/threads/approvals/imports) + Policy + scoping; chip-count == filtered-total per state (7A); lifecycle filter parameter; workspace PATCH (validation, owner-only, slug uniqueness) + rename audit write (11A).
