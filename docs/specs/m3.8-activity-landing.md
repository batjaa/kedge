# Spec: M3.8 — Activity feed & marketing landing

> Second module of the 2026-07-23 design-lock split ([M3.7 restyle & dashboard](m3.7-design-refresh.md) →
> **this** → [M3.9 web i18n](m3.9-i18n.md)). Depends on M3.7 (the dashboard layout hosts the feed;
> the landing ships in the restyled register). Eng-review decisions (2026-07-23) inlined by issue number.

## Problem Statement

Authors have no way to catch up: replies, accepted suggestions, re-scans, orphaned threads, and settling imports happen invisibly unless you open each document. And the anonymous SaaS home is a bare paste box — a stranger has no idea what Kedge is before pasting, which wastes the product's one shot at a first impression.

## Solution

A "Recent activity" feed on the dashboard, read from the audit log (instrumenting the review-side actions that never wrote audit events), with every row linking to its target. And the Open Harbor marketing landing as the anonymous SaaS home, with the working demo import in the hero.

## User Stories

1. As an author, I want a Recent activity feed (replies, accepted suggestions, re-scans, orphaned threads, imports settling, workspace renames), so that I can catch up after time away.
2. As an author, I want each activity row to link to its target (document section, project), so that catching up is one click.
3. As an author, I want a re-sync to appear as one digest line ("28 anchored, 2 relocated, 1 orphaned"), so that a busy re-sync doesn't flood the feed.
4. As a workspace member, I want activity to show only well-formed, safe fields (never IPs or raw audit internals), so that the audit table's operational data stays private.
5. As a new user with an empty workspace, I want a friendly empty-feed state, so that the dashboard doesn't look broken on day one.
6. As an anonymous SaaS visitor, I want a real landing page — what Kedge is, what's shipped, what's coming, self-host story — with the paste-a-URL demo in the hero, so that I understand the product before I try it.
7. As an anonymous visitor on a self-hosted instance, I want the sign-in branch unchanged, so that a private instance stays private-feeling.

## Implementation Decisions

**Activity instrumentation (write side).**
- Extend the existing `AuditLogger` seam to the review-side gaps: thread/comment created, suggestion accepted/declined, approval granted/gone-stale, import settled (ready/failed if missing), plus the M3.7 workspace rename. These writes also serve M5's inbox — the feed is deliberately a subset of what M5 will consume; the event-type vocabulary is a backed enum in one place.
- **Re-anchor outcomes aggregate** (1A): the re-sync/re-anchor path writes **one event per re-sync** with anchored/relocated/orphaned counts and thread ids in meta — never per-thread rows. (M5 re-derives per-thread relevance from meta if it needs it.) Matches the scan-report precedent.
- **Display context snapshots at write** (2A): callers pass display strings (doc title, section ref, actor-visible names) into meta; the feed renders from the row alone. Deleted subjects never break a sentence; titles read as they were at event time — which is what an audit trail should say. Morph hydration is used only to build the target link, and a dead target drops the link, not the row.
- Audit failure is logged, never thrown into the domain action (comment persistence must never depend on audit writes).

**Activity read (feed).**
- Policy-guarded, workspace-scoped, paginated endpoint with a **type allowlist** — only enum'd events with a user-facing sentence are exposed.
- **Allowlisted projection resource** (3A): the response emits only `{type, actor name/avatar, sentence fields from the meta snapshot, target ref, timestamp}`. `ip` and raw `meta` are never serialized — same independent-allowlist pattern as the integrations resource, proven by a serialization test.
- **Composite index** (10A): additive migration adding `(workspace_id, created_at)` to `audit_logs`, shipped with the endpoint.
- Feed renders actor avatar + sentence + target link + relative time; loaded on page load, **no polling/realtime** (M5 owns liveness). Untrusted strings (imported doc titles) render inert via normal React escaping — asserted by test.
- **Degradation** (A1): feed fetch failure → the panel renders nothing behind the existing degraded banner; the dashboard is never blocked. Empty workspace → designed empty state.

**Marketing landing (SaaS only).**
- The anonymous SaaS branch of the root route renders the Open Harbor landing (`docs/designs/variant-3-open-harbor.html` is the mockup of record): hero with the working demo paste box (existing demo-import flow, rate limits, SSRF guard — unchanged), capability tour, console shot, roadmap cards, self-host CTA.
- Content is statically authored marketing copy — curated by hand, never generated from ROADMAP.md. (Localized in M3.9.)
- Self-hosted edition: existing sign-in branch untouched; edition read from the config endpoint, failing closed to self-hosted, as today.

## Testing Decisions

Existing three seams.

- **Journeys**: *dashboard-activity* (seeded events render sentences linking to targets; empty workspace shows the empty state); *landing* (SaaS env: anonymous visit renders the landing and the hero paste runs the existing demo flow; self-hosted env: sign-in branch — edition-gating prior art from the demo-mode journeys).
- **API PHPUnit**: activity endpoint (scoping, type allowlist, pagination); **serialization test: `ip`/raw `meta` never appear in any payload** (3A — the PAT credential-hygiene test is prior art); **one aggregate row per re-sync** with correct counts (1A); write sites fire from their domain actions; **subject deleted → sentence still renders from snapshot, link dropped** (2A); audit-write failure doesn't fail the domain action.
- **Web vitest**: sentence rendering per event type; **untrusted title with markup renders inert**; feed degrade render (A1); relative-time formatting.

## Out of Scope

- Realtime/polled activity, inbox, mentions, digests, per-user relevance (M5).
- Landing i18n, hreflang/SEO alternates, URL-localized routes (M3.9 / Launch tail).
- Per-thread re-anchor audit rows (1A decided against; M5 re-derives from meta).
- Landing content CMS or ROADMAP-driven generation.

## Further Notes

- The event-type enum added here is the contract M5's inbox consumes — changing its values later is a migration, name them carefully.
- Landing copy is an editorial artifact; updating it is a deliberate act, reviewed like docs.
